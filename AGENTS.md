# AGENTS.md

# AI Diet Manager

## Purpose

This repository contains the development of AI Diet Manager, an AI-assisted nutrition application.

The current objective is to build a high-quality Minimum Viable Product (MVP) as a personal technical portfolio project while following good software engineering practices.

---

# Development Philosophy

Prioritize:

- simplicity
- readability
- maintainability
- incremental development
- clean architecture
- product thinking

Avoid unnecessary complexity.

Every important engineering decision should have a clear reason.

---

# Teaching Philosophy

The developer does not intend to become a React specialist.

When explaining concepts:

- explain why something exists;
- explain where it fits in the architecture;
- explain only what is necessary.

Avoid long theoretical explanations unless explicitly requested.

---

# Preferred Workflow

Whenever possible, follow this order:

1. Explain the objective.
2. Explain the architectural reason.
3. Implement.
4. Validate.
5. Document important decisions.

Prefer small iterations instead of large code generation.

---

# Code Guidelines

Use:

- English
- meaningful names
- reusable components
- readable code
- consistent formatting

Avoid:

- duplicated logic
- unnecessary abstractions
- premature optimization

---

# Documentation

Documentation is considered part of the project.

Whenever significant engineering or product decisions are made, update the corresponding documentation.

The Decision Log should always remain synchronized with the project's evolution.

---

# Product Philosophy

The application should prioritize:

- user experience
- accessibility
- personalization
- scalability

Technology exists to support the product—not the opposite.

---

# UI Philosophy

Preferred visual style:

- Apple-inspired
- minimalist
- modern
- dark-first
- clean
- subtle animations

The interface should feel calm and uncluttered.

---

# Portfolio Goal

This repository also serves as a technical portfolio piece.

Whenever appropriate:

- explain engineering decisions;
- highlight architectural reasoning;
- reinforce product thinking;
- identify good software engineering practices.

---

# AI Behavior

When proposing solutions:

- prefer quality over quantity;
- preserve architectural consistency;
- explain trade-offs;
- avoid unnecessary dependencies.

Do not replace existing architecture without a strong reason.

---

# Long-Term Vision

Possible future features include:

- AI nutrition coaching
- Apple Health integration
- food recognition
- wearable integration
- cloud synchronization
- analytics dashboard

Current development should keep these possibilities open without implementing them prematurely.
